# PPTX 제작 및 검수 절차

## 1. 입력과 권한 확인

다음을 확인하고 비워 둔 값을 임의의 기본값으로 채우지 않습니다.

- 대상 자료: 파일 또는 폴더의 정확한 경로
- 주제: 사용자가 제공한 주제 또는 자료에서 주제를 정해도 된다는 명시적 위임
- 출력: 최종 폴더와 파일명
- 사양: 화면 비율, 글꼴, 제목·본문 최소 크기, 예상 분량
- 디자인: 적용할 디자인 파일과 우선순위
- 자료 범위: 웹 검색과 외부 이미지·데이터 사용 허용 여부
- 노트: 발표 스크립트, 교사 발문, 출처 형식

기존 출력 파일과 충돌하면 자동 덮어쓰기나 자동 이름 변경을 하지 않습니다. 사용자가 미리 승인한 명명 규칙이 없으면 정확한 충돌 경로를 보여주고 덮어쓰기 또는 새 파일명 결정을 요청합니다. 원본 수정·이동·삭제, 외부 업로드·공유가 필요한 경우에도 정확한 대상과 영향을 보여주고 사용자 승인을 받습니다.

## 2. 원본 분석

1. 원본을 읽기 전용으로 열고 파일별 역할을 구분합니다.
2. 학습 목표, 핵심 주장, 근거, 수치 데이터, 오개념, 활동과 출처를 추출합니다.
3. 내용 자료와 디자인 자료를 분리합니다. 디자인 파일은 표현 규칙에만 사용하고 내용 근거로 확장하지 않습니다.
4. 웹 사용이 금지되거나 허용 여부가 없으면 검색, 이미지 검색, 외부 URL 열기를 하지 않습니다. 외부 보강이 과업에 필수일 때만 사용자에게 허용 범위를 묻습니다.
5. 자료에 없는 내용은 추정하지 않습니다. 안전한 구성 판단과 사실 추가를 구분합니다.

## 3. 제작 계획과 승인

제작 전에 다음을 사용자에게 보여줍니다.

- 슬라이드 수와 슬라이드별 한 문장 메시지
- 각 슬라이드에 사용할 근거 자료
- 텍스트·표·도식·차트·이미지의 구성 계획
- 디자인 규칙을 16:9에 적용하는 방식
- 글꼴 확인 방법과 예상 대체 글꼴
- 발표자 노트 구성
- 렌더링과 구조 검증 방법
- 생성할 파일과 최종 절대경로
- 사람의 판단이 필요한 `확인 필요` 항목

사용자가 계획 승인을 요구했거나, 되돌리기 어려운 작업·둘 이상의 결과 파일 생성·여러 후보 중 일부를 사용자가 골라야 하는 작업이면 현재 요청을 한 사용자에게 승인을 받기 전에는 PPTX를 생성하지 않습니다. 모든 입력을 일괄 처리하도록 지정된 경우는 선택 승인이 필요하지 않습니다. 새 파일 하나를 사용자가 지정한 빈 경로에 만드는 등 대상이 명확하고 되돌릴 수 있는 작업은 별도 계획 승인이 요구되지 않는 한 진행할 수 있습니다.

## 4. 웹 디자인 규칙의 16:9 변환

기본 슬라이드 크기는 13.333 × 7.5인치입니다.

- 기준 화면 폭과 높이가 주어졌으면 `슬라이드 좌표 = 웹 좌표 ÷ 기준 화면 크기 × 슬라이드 크기`로 비례 변환합니다.
- CSS 글자 크기는 `1px = 0.75pt`를 출발점으로 삼되, 제목 28pt 이상과 본문 18pt 이상을 우선합니다.
- 기준 화면 크기가 없는 단독 px 간격은 96px/in를 참고값으로만 사용하고 슬라이드 여백, 한글 줄바꿈과 가독성에 맞게 재조정합니다.
- `vw`, `vh`, `rem`, 반응형 재배치, hover, 애니메이션, 고정 위치, 웹 필터는 정적 슬라이드에 직접 대응하지 않습니다. 의미가 유지되는 정적 표현으로 바꾸고 판단이 필요한 항목은 `확인 필요`로 표시합니다.
- 색상, 여백, 모서리, 카드 위계와 이미지 비율은 원본 디자인의 관계를 유지하되 화면을 그대로 축소하지 않습니다.

## 5. 슬라이드 설계와 제작

1. 슬라이드마다 학습자가 기억할 메시지 하나를 정합니다.
2. 제목은 28pt 이상, 본문은 18pt 이상으로 설계합니다.
3. 수치 데이터가 있는 경우에만 편집 가능한 PowerPoint 차트를 만듭니다. 차트는 축, 척도, 면적·길이·위치 등으로 수량을 부호화하는 시각화입니다. 단위, 범주, 축, 범례와 출처를 확인합니다.
4. 수치 데이터가 없으면 차트를 만들지 않고 편집 가능한 도형, 연결선, 표 또는 비교 카드로 단계와 관계를 표현합니다.
   - 근거 데이터가 없으면 막대 길이, 아이콘 개수, 면적, 간격의 차이로 크기나 비율을 암시하지 않습니다.
5. 이미지를 사용하면 출처를 기록하고, 장식 이미지가 메시지나 가독성을 방해하지 않게 합니다.
6. 모든 텍스트와 도형은 슬라이드 경계 안에 두며 반복되는 구성의 간격과 정렬을 통일합니다.

## 6. 발표자 노트

모든 슬라이드 노트에는 다음 세 항목만 둡니다.

1. **발표 스크립트**: 슬라이드 문구를 그대로 옮기지 않은 자연스러운 한국어 3~5문장
2. **교사 발문**: 학생에게 던질 질문 한두 개, 각 한 문장
3. **[Sources]**: 주장, 데이터, 이미지와 도표의 실제 출처

출처가 없으면 `[Sources] 해당 없음`, 확인하지 못했으면 `[Sources] 확인 필요`로 기록합니다. 예상 응답, 오개념, 진행 팁 등 네 번째 항목을 추가하지 않습니다.

## 7. 저장 후 구조 검증

최종 PPTX를 다시 열어 다음을 확인합니다.

- 파일 존재와 실제 최종 절대경로
- 정상 재열기와 전체 슬라이드 수
- 16:9 화면 비율
- 제목·본문 최소 글자 크기
- 지정 글꼴의 실제 적용 또는 대체 글꼴
- 모든 슬라이드의 노트 존재
- 각 노트의 발표 스크립트 3~5문장, 교사 발문 1~2개, `[Sources]`
- 차트·표·도식의 편집 가능성
- 결과물이 지정 위치에만 생성됐는지 여부
- 원본이 수정·이동·삭제되지 않았는지 여부

글꼴은 운영체제 또는 프레젠테이션 제작 환경의 설치 글꼴 목록에서 확인하고, 생성된 PPTX의 실제 텍스트 실행 속성도 다시 검사합니다. 지정 글꼴이 없으면 임의 설치하지 않습니다. 한글 글리프 범위와 글자 폭이 유사한 대체 글꼴을 사용하고 대체 글꼴명과 `확인 필요`를 보고합니다.

## 8. 전체 렌더링 검수

`presentations:Presentations`가 안내하는 현재 환경의 렌더링 도구로 모든 슬라이드를 이미지화하고 전체 몽타주와 개별 슬라이드를 함께 봅니다. 단 한 장이라도 렌더링이 누락되면 전체 렌더링 완료로 판정하지 않습니다.

- 글자·도형·이미지의 잘림과 겹침
- 제목, 본문, 출처의 읽기 크기
- 여백, 정렬, 카드 간격과 시선 흐름
- 대비와 색상 일관성
- 한 슬라이드에 메시지가 과도하게 섞였는지 여부
- 차트 축, 범례, 단위와 데이터 레이블
- 빈 공간과 지나치게 조밀한 영역

글자나 도형이 경계를 벗어나거나 서로 겹치는 경우, 최소 글자 크기보다 작아지는 경우, 핵심 문구가 배경과 구분되지 않는 경우, 이미지 비율이 왜곡되는 경우는 수정 대상입니다. 단순한 취향 차이는 자동으로 결함 처리하지 않고 필요하면 `확인 필요`로 분리합니다.

발견한 문제를 수정한 뒤 다시 렌더링합니다. 같은 유형의 실패가 세 번 반복되면 무한히 재시도하지 말고 원인, 시도한 방법과 대안을 사용자에게 보고하고 진행 방향을 묻습니다.

## 9. 완료 보고

다음 네 항목으로 보고합니다.

| 항목 | 보고 내용 |
|---|---|
| 생성한 파일 | 실제 파일명과 최종 절대경로 |
| 원본 상태 | 수정·이동·삭제 여부 |
| 검증 결과 | 재열기, 16:9, 슬라이드 수, 노트, 글꼴, 편집 가능성, 렌더링 결과 |
| 확인 필요 | 사람이 확인해야 하거나 검증하지 못한 사항 |

실제로 검증한 사실만 완료로 표현합니다. 링크는 파일 존재를 확인한 뒤 실제 최종 경로로 제공합니다.

사용자가 이미 정한 화면 비율, 최소 글자 크기, 전체 노트, 렌더링 검수 같은 필수 요구는 마감이 촉박하다는 이유로 일부 적용 여부를 다시 묻지 않습니다. 충족할 수 없으면 해당 결과를 완료로 보고하지 않고 부족한 항목과 가능한 대안을 알립니다. 부분 초안은 사용자가 초안 제공과 파일명을 명시적으로 승인한 경우에만 별도 결과로 제공합니다.
